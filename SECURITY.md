# Security policy

## Reporting

Please use **GitHub → Security → Report a vulnerability** for credentials, private infrastructure details, personal-data exposure, unsafe links or exploitable code. Do not open a public issue containing sensitive details.

## Public-release boundary

This repository must never contain credentials, private hostnames or IPs, home-directory paths, database/service configuration, raw operational receipts, private source identifiers, copied third-party page bodies, personal addresses or unnecessary contact details. Use reserved examples (`example.org`) in tests.

The catalogue is metadata-and-links only. Treat a public URL as access evidence, not permission to redistribute. If in doubt, stop and label the rights state `pending`.

Supported security fixes apply to the default branch. Static files run without a backend; report any script injection, unsafe external navigation or supply-chain concern.
